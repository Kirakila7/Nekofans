# 工作台 0.14.2：聊天回复可见性

用户配置 DeepSeek 后认为桌宠没有文字回复。现场诊断发现本机已有成功助手记录，短句请求也正常返回；显示层仍沿用工作状态气泡的 10 秒超时，输入框与悬停检查器会遮住回复。此外，错误提示会被同轮空回复清掉，历史恢复也可能在失败后展示更早的成功内容。

- API 模式的最新回复和错误保持可见，开始下一轮或切换后端时清理；其他桌宠工作提示仍沿用原定时行为。
- 主角色 API 模式不启用任务悬停检查器；回复在输入框打开时也可见，长文字可滚动、选择，并支持键盘聚焦。
- 通知优先于空回复或旧回复；失败后的历史恢复只接受最新一条为 assistant 的消息。
- 退出 API 模式只清理一次持久回复，不覆盖后续本机 N.E.K.O. 的新回复。

子代理缺席的诊断：当时当前存档没有 `subagent/catalog` 或 `subagent/start` 记录，先前任务只使用了普通工具和后台作业。随后在新会话明确要求调用一个原生子代理，真实 catalog 生成了 continuable 子会话并成功返回。该新建验收子代理通过应用自有菜单设为常驻供用户查看，没有导入旧版子代理或伪造会话。

真实服务诊断使用固定短句：DeepSeek API 返回 `connection-ok.`，原生子代理返回 `subagent-ok`。它们只验证连接与显示链路，不作为语音或自然对话质量验收。账号密钥由用户在本机设置，诊断未读取或上传密钥；子代理提示明确禁止文件访问与命令执行。
