# 工作台 0.14.0：Issue #2 第一批交付

此文保留 0.14.0 的历史验收记录。社区展示方式已在 [0.14.1](IMPLEMENTATION_v0.14.1.md) 改为同一工作台右侧内容区。

本批完成 Kirakila7 工作台线的主聊天/轻量记忆接线，以及用户定制 DSH 侧栏的“＋ / 社区”同排行。它不关闭整个 Issue #2；原生语音、双记忆原生适配、社区单点登录/通知/卡牌和发行安装仍分别推进。

## 改动范围

- 在工作台主进程装配已有 `openMainChat`、scoped memory 和 summary 服务；没有另写聊天或记忆后端。
- API 设置支持 OpenAI 兼容 / Anthropic、地址、模型、密钥保存/清除；主角色输入支持流式回复、停止与失败恢复，最大 8000 字。
- Electron safeStorage 密钥文件与配置、persona、SQLite 均归本应用 `data/main-chat/`；禁用明文或 `basic_text` 回退，不把 API 聊天再次写入桌宠 `state.json`。
- 记忆界面支持候选确认、编辑、删除、摘要来源及同一 SQLite 聊天记录；DSH 任务备注单独保存和展示。
- 本机 N.E.K.O. 连接器与 Chat API 互斥；切换持久化失败不改变模式，取消与迟到连接/回复有代次隔离。
- 定制 B0 侧栏将原新会话节点显示为“＋”，社区位于同一行。保留原节点、事件、可访问名与 disabled 状态，不搬动或克隆原按钮；折叠、重绘和卸载均有回归。
- 社区继续打开已有 `https://community.project-neko.cn/feed` 的独立沙盒窗口，不新增另一套社区。

按已认领所有权，仅修改 `apps/neko-workbench/`（不含 `framework/`）与 `tests/neko-workbench/`。共享 `packages/`、`services/`、根脚本/配置及 Windows 入口没有改动；参考源码哈希也没有降低或重写。

模拟接口、虚构密钥与临时数据库用于自动测试。实机窗口验证没有发送真实模型请求、保存真实聊天 API 密钥、主动登录、充值或操作社区内容；不把模拟 SSE 当作真实供应商联调或用户试听通过。

DSH 官方账号组件在本机环境中可显示既有官方登录状态；独立 DSH_HOME 不等于本批已证明上游所有设备级登录态完全隔离。本批未主动导入/复制该凭据，含账号余额的截图不上传仓库。

离线 HTML 只用作开发 fixture，本批实际界面结论来自运行中的定制工作台。QA 使用临时存档，与正式应用入口分别保存；原生语音、社区登录/OAuth 回跳、Windows 实机与发行包均未作为本批通过项。

## 运行资源提示

`NEKO_WORKBENCH_ELECTRON` 应指向纯 Electron 运行时。自带 `Resources/app` 或 `app.asar` 的旧产品包可能优先执行自己的旧入口，忽略传入的本项目目录；路径预检只确认可执行文件存在，不证明它是正确的开发运行时。
