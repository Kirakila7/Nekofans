# B 站视频卡片与社区聊天室：接入草案

本文件记录方案，不代表社区聊天室或跨站发送已经实现。

## 期望体验

1. 在工作台 B 站视频页选择“分享到聊天室”。
2. 进入 N.E.K.O. 社区，让用户选择聊天室或会话，并在可编辑的草稿中看到视频卡片；由用户确认发送。
3. 接收方看到卡片，点击后在当前聊天界面观看，返回时保留原来的会话和输入。播放器不在消息出现时自动加载或播放；无法内嵌时提供“在 B 站打开”入口。

## 可复用的现有能力

目前工作台可从当前可见视频页复制规范化的官方链接。N.E.K.O.Verse 的现有私信是独立网站：当前消息类型为文本、图片和贴纸，普通文本尚未渲染成视频卡片。其插件展示页面已经有严格 B 站链接解析与官方播放器的实现，可以作为社区侧的参考；不能直接当作已存在的聊天室接口。

## 最小兼容方案

- 社区先沿用文本消息，识别**完整、独立**的官方 B 站 BV 视频链接并显示卡片；旧版客户端仍能看到原始链接。不自动把普通文本中的任意网址变成 iframe。
- 卡片最初只展示可信的来源和视频标识；若将来提供标题或封面，应由社区通过明确、受控的服务端能力获取并处理失败，不由接收方浏览器访问任意地址。私聊中避免在阅读消息时自动请求外站封面。
- 用户点击观看后，社区可复用已有的官方播放器 URL 构造方法，限制来源与参数；视频是否允许嵌入、登录、播放和清晰度由 B 站服务及浏览器环境决定。不可用时保留官方原站链接。
- 工作台向社区交接时只传经过校验的官方视频标识和必要的分 P 信息；接收端必须再次校验。社区需要设计明确的受控草稿入口和会话选择，不共享工作台与社区的 cookie，也不自动发消息。
- 若未来要保存封面、标题或多种媒体，另行设计版本化的消息内容与旧客户端回退；需要协调现有私信与尚在规划中的聊天室，不预设其数据结构相同。

## 接入前需要验证

社区聊天室的仓库、消息协议和权限；草稿交接及发送确认；官方播放器对具体视频的嵌入与登录行为；工作台和浏览器内的播放、返回与失败回退。本仓库不会创建社区消息或宣称已分享。
