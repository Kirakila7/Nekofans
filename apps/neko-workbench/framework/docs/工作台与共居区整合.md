# 工作台与共居区整合说明

本文沿用附件路径记法：`desktop/` 在本仓库对应 `apps/neko-workbench/`；`src/`、`config/`、`reference/`、`tests/` 等框架资料对应 `apps/neko-workbench/framework/` 下的同名目录。

## 本轮纳入什么

v3 在原 v2 双记忆框架旁加入 `desktop/` Electron v0.13.0 原型源码。保留的 `reference/memory-hub.mjs`、`tests/memory-hub.test.mjs`、人设和皮肤合同不改写。原型的 UI、真实 DSH 路由和只读账号余额有实现；双记忆服务没有接入该原型。

| 工作 | 当前实现位置 | 边界 |
|---|---|---|
| 三个角色位 | `desktop/workbench-roles.cjs`、`workbench-preload.cjs`、白标 client | Yui / 大肥鱼 / Claude小姐，固定 ID 与顺序；仅 `bigfish` 启用，名字、头像可自定义 |
| 真实工作台入口 | `desktop/main.cjs` 的 `workbench:roles` 与 `rolesState()` | `workspaceSessionId` 指向现有 DSH 会话；换名字/头像不新建、不清空、不替换会话 |
| 插件 / 自动化 / More | `desktop/embedded-dsh/b0-skin/packages/dsh-client-ui-white-label/lib/client.js` | 收在大肥鱼入口，保留原生控件、动作及权限；不是另建一套插件或自动化执行器 |
| 开发喵账号入口与共居区 | `desktop/embedded-dsh/account-habitat-source.js`、同名 CSS | 开发喵名字在头像上方；右侧上方显示余额，下方是独立底色区域；当前只有一只原版大肥鱼 |
| 官方余额读取 | `createNekoAccountBalanceReader()` | 通过 `ctx.remote.account.getState/getBalance` 只读获取，保留官方原币种与数据来源；失败显示暂不可读取 |
| 原版大肥鱼素材 | `desktop/assets/idle.webm`、账号区域 poster 资源 | 复用原 dsh-pet 动作；页面不可见或减少动态效果时暂停，不生造“在工作”等状态 |
| 全局主题 | `desktop/workbench-appearance.cjs`、`embedded-dsh/avatar-theme-source.js` | 五个内置头像与本地 custom 图像取色，颜色传播到全 UI；不更改角色、账号或任务 |
| 双记忆 | 根目录 `src/memory-contracts.ts`、`reference/memory-hub.mjs` | 原合同与模拟适配器测试，未导入 `desktop/main.cjs`、未联通真实日记或 N.E.K.O. |

显示角色位与人格记忆不是同一个表。当前主桌宠内部 actor ID 是 `main`；v2 人设与未来记忆 ID 仍是 `bigfish`。二者后续须显式映射，不能因 UI 已经有“大肥鱼”而声称独立人设存储已经完成。

## 已保留的原型能力

桌宠透明窗口、原版动作、完成/错误反馈、单行输入、气泡、悬停、真实子代理目录、常驻、昵称、显示上限、停止与内嵌 DSH 继续使用现有代码。主角色和子代理状态分离；当前主聊天与 DSH 工作流仍分别管理。

工作台中的角色改名与头像更新只影响对应显示配置。Yui、Claude小姐当前不可进入真实后端，选择时应明确显示未接入；不能用与大肥鱼相同的 DSH 会话伪装成三个独立角色后端。

账号区域使用原生官方认证状态，DeepSeek 对应大肥鱼。开发喵只是入口的显示身份，不是新账号；主题选择也不是模型或账号切换。原账号菜单、充值和其他原生动作保留。

配置示例的账号连接列表保持为空，由运行时投影真实账号状态；没有登录时不构造一只“已登录”的大肥鱼。当前只有 DeepSeek 人物呈现被启用，其他 provider 与角色位不构成已登录账号。

余额保持 CNY / USD 原币种；按官方 UI 的币种选择规则显示单个钱包，不做换汇和跨钱包求和。源码包不携带真实余额截图、凭据、Cookie 或本机账号状态。独立预览的“示例”额度不能作为真实钱包值。

## 数据分开存放

| 数据 | 当前原型或合同位置 | 隔离要求 |
|---|---|---|
| 全局头像 / custom 图像 | 运行后 `desktop/data/workbench-appearance.json` | 只决定显示和背景主题 |
| 三角色位的名字 / 头像 | 运行后 `desktop/data/workbench-roles.json` | 角色 ID、数量、顺序、启用状态由代码锁定 |
| 桌宠与 DSH UI 运行状态 | 运行后 `desktop/data/state.json` | 不充当人格记忆库；其中 `state.memory` 是任务备注 |
| DSH 会话 / 账号 | 官方宿主及真实会话路由 | 不向记忆合同暴露凭据或会话权限 |
| 人设 / 皮肤 | `config/persona.bigfish.json`、`config/skin.bigfish.json` | 固定 `personaId=bigfish`，人设与外观分别管理 |
| 未来日记 / 事件 / 原始聊天 | v2 配置合同中的 `${APP_DATA}/personas/bigfish/` 等 | 需实现可靠持久化与迁移，不以 `sessionId` 命名记忆空间 |

前三项是原型运行时会生成的本机文件，本包未打入已有 `data/`。后两类业务存储与适配仍需开发，不把配置样例当成已创建的服务。

## “养鱼”到 MemoryHub 的桥接位置

以下是**后续实现方案**，不是本轮新增的运行接口。`config/main-agent-menu.json` 继续只是菜单合同；新增顶层“养鱼”入口为 planned / disabled，原有养鱼子项保持设计定义。当前桌面代码没有加载该合同，也没有创建 `MemoryHub` 实例。

1. **主进程创建协调层。** 在 `desktop/main.cjs` 初始化阶段接一个独立的记忆服务封装，以固定 `personaId: 'bigfish'` 创建根目录参考内核的 `MemoryHub`。提供 `snapshot` 恢复和真正可靠的 `persist`；不能使用构造器默认的空 `persist` 宣称落盘成功。主进程持有适配器、事件库和秘密配置，渲染器只收状态。
2. **实现两端适配器。** 按 `ReplicatedMemoryAdapter` 提供 `health/pull/push/recall`，先做日记的来源绑定、稳定 ID 与修订侧表，再做目标 N.E.K.O. 版本兼容网关。只有协议版本及 `pull/push/idempotency/tombstones/privateMemory` 全部满足时才允许同步和模式切换。不得直接改写正在运行的原生记忆文件或索引。
3. **单独补召回路由。** `MemoryHub` 当前实现的是 `add/sync/switchTo/snapshot/records` 等同步协调，不是聊天服务，也没有直接的 `recall()`。新的 `MemoryRouter` 应读当前 mode，仅向对应 adapter 调用 `recall(query, budget)`。`MemoryModeController.current/status` 的 UI 封装也需另行实现，不能把合同接口当成已有方法。
4. **接主聊天而非 DSH 任务分支。** `desktop/main.cjs` 的 `pet:call` → `prompt` 已区分 `a.id === 'main'`。未来 ChatService 在主角色分支组合人设、原始聊天与召回，再交给独立 `ChatProvider`；回复后保存消息、来源和候选记忆。不要把该链路塞进后面的 DSH `rpc('prompt', …)`，也不要把任务备注自动提升为用户确认事实。
5. **保留可选 N.E.K.O. 传输的独立边界。** `desktop/neko-chat.cjs` 有本机角色/聊天传输代码，但没有实现上述复制协议。其设置或连接可能涉及本机角色创建，必须由单独的用户操作触发；本轮不执行。N.E.K.O. 聊天可连接不等于 `NekoMemoryAdapter` 已就绪。
6. **挂“养鱼”控制面。** 在 `desktop/main.cjs` 的主 Agent `mainMenu()` 下按合同增加“养鱼”集合；通过独立、有限的方法白名单连接设置 UI。可参考既有 `assertWorkbenchCaller()`、`workbench-preload.cjs` 的来源校验与订阅取消方式，但不要复用角色 `update` 或开放任意 IPC。未就绪功能明确显示待接入，不自动启动服务。
7. **按动作映射。** `fish.start` 对应配置校验/恢复，`fish.pause` 只暂停生活代理；`memory.mode.*` 走 `switchTo()` 的准备、恢复点、同步和冲突检查；`memory.sync` 走 `sync()`；`memory.status` 显示待同步、冲突及各端健康状态；`fish.memories` 通过独立受限接口查询、确认、修改、删除与导出。

自动同步须在持久化、适配能力和授权都就绪后启用。失败时保留原 mode 和数据，不能只切 UI 的选中项。暂停养鱼或记忆同步不得停止用户的 DSH 任务，也不得改变真实子代理目录。

B站生活模块、扫码与对外发送仍是后续合同；不因为原附件描述了一个向导就自动登录、启动或发送。语音记忆与 PNGTuber 也不在本轮运行范围内。

## 后续验收

| 阶段 | 必须观察的结果 |
|---|---|
| 当前源码与离线协议 | 原 `node --test tests/memory-hub.test.mjs` 通过；原 reference、tests 与 `bigfish` 身份合同保持原样 |
| 桌面运行 | 在相容官方 Electron / DSH 环境启动；角色、菜单、原任务动作与状态保持；缺依赖时如实失败 |
| UI / 账号 | 姓名在开发喵头像上方、余额在生活区上方、一只原版大肥鱼；换五套头像或 custom 只改背景，不换账号/会话；未登录或余额不可读不显示伪造值 |
| 日记与持久化 | 原始聊天有稳定消息 ID；重启恢复；落盘失败不提交事件、不推进游标；任务备注不被当作已确认记忆 |
| 复制与删除 | 重放 10 次不重复；来回同步不循环；并发保留分支；tombstone 不被旧备份复活；恢复须显式操作 |
| 角色与隐私 | 其他 persona 事件拒绝；私有条目只到同角色私有存储；凭据、DSH 权限与会话状态不进入记忆 |
| 模式切换 | 目标离线、能力不足、保存失败、部分 ack 或未处理冲突时不切换；成功后才保存新主召回来源 |
| 真实适配 | 使用明确指定的 diary/N.E.K.O. 版本、测试档案和授权，验证真实读写后再报告联通；模拟测试不能替代 |
| 发布 | 清洁机器安装、官方运行时兼容、素材许可、签名、首次配置、升级保留数据与卸载边界全部通过 |

本次整合的验证限于离线检查，原记忆测试使用模拟适配器；不启动真实 N.E.K.O.、B站或模型任务。未把 prototype 源码 ZIP 宣称为签名、捆绑运行时且下载即用的发行版。
