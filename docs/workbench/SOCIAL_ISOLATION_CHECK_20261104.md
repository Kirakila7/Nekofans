## 覆盖的链路

- 串门：两个合成参与者邀请、接受、各自生成共六句话、身份/签名、消息一致、历史按账号隔离、拒绝、停止、登录恢复、撤销凭据和失败回滚。RTC 厂商传输使用替身；这不代表两台真实设备已互通。
- 一键养鱼 / QQ：已选渠道启动、暂停、待扫码取消、登录门槛、并发启动、旧状态不覆盖新操作、工作台桥接与 UI、监听只读限制。未登录时仍要求登录，不把测试响应当作真实“在线”。
- 主 agent 记忆：合成 B站/QQ 经历进入真实主记忆控制器与持久事件存储，经同步、召回后用于桌面主动发言；去重、删除、重启和公共聊天室召回隔离均验证。模型与远程记忆传输为本地替身。
- 聊天室：独立模式主动回应新房间消息，概率、60 秒冷却、每日额度、提及、主人触发、管理员禁用、静音、删除、断网取消、账号就绪与私人主聊天隔离。当前“自由参与”是消息触发，默认概率 0.15，并非空房间定时自言自语。
- 社区日常：真实主聊天存储提供今日素材，生成不召回私人记忆，不伪造用户历史；纯文本输出、开关、账号绑定、工作避让、时间窗口、同日并发与重启去重、来源变化、取消、保存失败及不确定投递不重发。真实 HTTP 环回测试验证 `/api/users/me` 与 `/api/posts` 的顺序、同令牌、multipart 字段、错误账号、重定向与 401 拒绝，不产生真实社区帖子。详见 [COMMUNITY_DAILY.md](COMMUNITY_DAILY.md)。

## 修复与边界

本次修复了旧测试夹具缺少 `ipcMain.removeHandler`、窗口名未跟随 Nekofans 更名、账号尚未加载便设置大厅模式，以及退出夹具缺少当前 disposer 的问题。没有降低生产账号就绪检查。符号链接测试现在只在 OS 不允许创建测试链接时明确跳过该子项。

社区自动发布需要串门 OAuth 注册参数、已登录社区账号、真实服务端发帖权限和可用主聊天模型。本次没有验证生产账号的发帖授权；默认开关保持关闭。普通安装包尚未自动配置串门 OAuth，网页会话不会被复制给主进程。新功能仅在当前源码工作树，之前交付的 EXE 未重打包，未推送 GitHub。

## 本机复现

用 Node 24 执行 `node _sandbox/social-isolation-20261104/run.cjs` 可复现完整分组。DOM 依赖来自独立的 `.nekofans-build/test-dom/node_modules/jsdom`，由 `NEKO_DOM_DEPS` 注入，不安装到产品依赖。新功能专项也可直接运行：

```powershell
node --test tests/neko-workbench/community-daily.test.cjs tests/neko-workbench/community-daily-http.test.cjs tests/neko-workbench/community-daily-main.test.cjs tests/neko-workbench/channel-memory-integration.test.mjs
```

隔离运行器需要创建合成临时文件并连接本机 HTTP 测试服务；受限沙箱禁止临时文件重命名和环回请求时会产生环境错误，应在允许这些本地测试操作的运行环境执行。不要用修改生产保护逻辑的方法消除此类错误。
