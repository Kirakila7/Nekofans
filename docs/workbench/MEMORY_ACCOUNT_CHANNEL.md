# DeepSeek 账号记忆通道

2026-11-04，0.28.41 源码后续改动。此前交付的大肥鱼图标版安装包不含此改动，需要重新构建或运行当前源码才能使用。

## 使用

主 agent 选择 DeepSeek 工作台账号并完成 DSH 登录后，在记忆窗口的「N.E.K.O. 记忆组件与整理模型」保留勾选「使用当前聊天通道整理记忆（账号 / API）」。保存并连接，或点击「立即处理待存记忆」。无需另外填写 API Key；整理调用沿用账号的模型额度。启动健康检查只确认账号和组件状态，本身不生成模型回复；后台待处理记忆可能随后产生整理请求。

独立 API 模型仍可通过取消勾选配置。API 聊天模式保留原来的加密密钥通道。N.E.K.O. 社区登录不替代 DeepSeek 模型账号登录。

## 实现与边界

- Electron 将原生 Python 记忆组件的 OpenAI 兼容请求，交给独立 `memory-account-*` RPC，再调用现有 DSH 账号 LLM 服务；模型固定为现有账号路线的 `deepseek-flash`。
- 仅监听本机 `127.0.0.1` 随机端口。每次启动生成短期本地令牌，经工作进程标准输入传递；不提取 DeepSeek 账号凭据，不保存到 API 配置，不显示在记忆视图。
- 只支持有界文本聊天补全；拒绝网页 Origin、无效令牌、工具调用、多模态输入及其他接口。兼容普通响应及完成后一次性发送的 SSE 响应；JSON 输出要求以提示传入，不宣称供应商原生严格结构化输出。
- 记忆请求串行执行，与陪伴私聊、聊天室、主动搭话分别维护取消锁。每次请求重新检查登录；退出账号、关闭应用、切换模型路线或断开客户端会阻止或取消过期工作。
- 原生记忆选择的材料会发送给 DeepSeek 进行整理，消耗相应账号额度。数据库与记忆文件仍保存在当前本机用户目录，没有新增云端记忆备份或账号同步。
- 不创建 DSH 工作会话、项目、工具任务，也不附加陪伴聊天的额外历史或召回数据。原生组件提交的记忆材料按原请求传递。整理失败保留原有待处理记录。

## 验证

使用合成材料验证本机认证、普通响应/SSE、JSON 提示、请求限制、账号退出、错误脱敏、并发串行、取消、主聊天隔离、模型切换、非敏感状态投影。实际内置 Python 3.11.9、安装的 OpenAI SDK 和原生 `ChatOpenAI` 已请求通过；真实 Python 记忆工作进程完成健康检查、经历提取、持久化及事件拉取。上游账号 LLM 使用测试替身，没有访问用户账号、消耗用户额度或验证供应商实际响应质量。
