# 统一工作区：DSH、Codex 与 Grok 接入计划

更新：2026-10-28

状态：方案待认领、待开发。目标是沿用用户当前的 N.E.K.O. 工作台，在左侧共用项目列表，并在同一个项目下选择 DSH、Codex 或 Grok Build 的真实任务会话。本文件不表示三个 Agent 已接入或已分派负责人。

## 用户体验

左侧保留现有工作区和项目入口。同一项目显示一次；其下可以分别列出各 Agent 的会话，例如：

```text
项目：猫娘计划
├─ DSH · 角色与工作台接入
├─ Codex · 社区界面开发
└─ Grok · 资料研究
```

用户在项目中选择 Agent 并新建任务，点击已有会话时，右侧显示该会话实际的消息、进度和结果。未安装、未登录、断开或能力不可用的 Agent 要显示真实状态和连接入口，不能创建假会话。首次接入和认证由用户主动操作，不增加强制开屏教程。

项目路径可共用；各 Agent 的会话 ID、历史、账号、额度、工具审批和运行状态独立保存。外观选择不改变模型或后端身份。主角色保持稳定；中号任务形象代表真实任务，小号子 Agent 形象仅在对应后端提供真实委派信息时出现，不能把 subsection 或普通会话伪装成子 Agent。

## 当前状态

- 现有侧栏中的工作区及会话基于 DSH 原生组件；工作台桥接直接使用 DSH agent、session 和 subagent 接口。项目列表可以作为统一入口的基础，但不能直接把其他后端的会话 ID 当作 DSH 会话。
- 尚未发现工作台中的 Codex 或 Grok 独立会话适配器；下文均为待完成计划，不代表实机接入成功。
- 用户已选择只使用新版存档，任务产生时显示相应角色。适配不得默认导入旧会话或旧角色，也不得将工作台整体迁移作为桌宠和现有 DSH 使用的前提。

## 实现与待认领分工

| 工作线 | 负责内容 | 交付 |
| --- | --- | --- |
| 项目注册与侧栏 | 定义项目 ID、用户选定的规范路径、显示名及仓库元信息；与现有 DSH 工作区做明确映射。 | 项目列表跨后端共用；新建、移除、重启恢复可验证，保留用户现有文件和未提交修改。 |
| 后端接口与 DSH | 定义按后端区分的会话标识、能力、消息、流式事件、权限请求、取消、恢复和错误接口；保留现有 DSH 桥接。 | 一个真实 DSH 任务可通过统一侧栏执行、停止并恢复，不破坏现有桌宠与任务显示。 |
| Codex 适配 | 根据 [Codex SDK / app-server 官方说明](https://developers.openai.com/blog/codex-as-a-platform)接入指定项目目录、真实会话、事件、审批及取消/恢复。 | 实际 Codex 任务运行并显示结果；未安装、未登录或无对应能力时提供明确状态。 |
| Grok 适配 | 以用户选择的 [Grok Build 官方方式](https://docs.x.ai/build/overview)接入，评估 ACP、会话、审批及事件能力；不得把单独 Grok 模型接口冒充完整 Agent。 | 实际 Grok 任务运行并显示结果；未安装、未登录或能力不支持时明确说明。 |
| 形象与真实状态 | 映射不同后端的任务与子 Agent 事件，维持主／任务／真实子 Agent 的三档形象；按后端能力显示。 | 真实事件驱动出现、运行、完成和消失；未提供事件时说明不支持，不虚构委派。 |
| 集成与验收 | 协调共享文件与接口，处理同项目并发变更，执行真实任务及隐私检查。 | 形成可审阅 PR、测试记录和未验证项；保持私人仓库、未经用户要求不合并。 |

上表是待认领的职责，不表示已创建任务或指派给特定人员。统一接口、主进程、侧栏共享文件由协调方收口，其他工作线先在独立模块和测试中实现，避免多人同时覆盖同一文件。

## 会话与并发约定

1. 统一项目记录保存用户选择的路径与后端会话映射；每条会话必须有真实来源与后端自己的标识。不同后端不自动共用聊天历史、角色记忆或子 Agent 状态。
2. DSH、Codex 和 Grok 各自使用对应的登录与额度；凭据由各自受信任的存储和运行时管理，不写入项目、侧栏或聊天记录。不能用头像变化冒充后端切换。
3. 默认应让用户明确看到哪个 Agent 正在访问或修改哪个项目。并行任务要检测同一工作树的实际变化并提示冲突；需要隔离时可按任务使用独立 Git worktree，保留原工作树和未提交更改，合并由用户审查决定。非 Git 项目需提供不依赖 worktree 的冲突处理方式。
4. 各引擎的权限请求、取消和恢复通过各自协议处理；不默认自动批准。后端无法提供某项能力时要如实展示，不能伪造运行中、成功或子 Agent 事件。

## 验收

- [ ] 同一真实项目只显示一次，可为 DSH、Codex 和 Grok 分别创建会话；选择其中一个会打开对应的真实消息和结果。
- [ ] 每个已安装并登录的后端完成一次真实项目任务，验证任务进度、错误、停止和会话恢复；未安装/未登录/断网分别有明确提示。记录系统、版本及不可用能力。
- [ ] 项目路径可共同访问，但会话 ID、记忆、登录、额度与审批不混用；切换外观不更换后端。
- [ ] 并发修改同一文件时可检测并提示；使用隔离工作副本时保留原项目未提交更改，用户可审查结果。非 Git 项目也有明确行为。
- [ ] 中号任务和小号子 Agent 只由实际任务及委派事件驱动；不支持子 Agent 事件的后端显示能力限制。
- [ ] 在独立测试存档运行相关自动化测试，并分别记录本机 DSH、Codex、Grok 的真实集成结果；模拟测试、真实运行及用户验收分开报告。
