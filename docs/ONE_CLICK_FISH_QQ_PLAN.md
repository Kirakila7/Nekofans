## 目标

用户只需使用工作台已登录的 DeepSeek Harness 账号，在主角色右键点击「开始养鱼」；尚未授权时，在同一个工作台设置面板分别扫码连接 B 站和 QQ 机器人，完成所选渠道的必要授权后继续启动。已授权的渠道下次自动跳过扫码。养鱼和 QQ 保留独立的状态与暂停控制，也提供统一开始/暂停入口。

**模型费用目标：** QQ 与 B 站养鱼都复用工作台已登录账号所支持的模型调用路线和额度，不要求用户额外创建或填写独立 API Key，不新增平台收费。当前宿主默认路线为 `deepseek-account / deepseek-flash`；该账号路线与 DeepSeek 开放平台 API Key 是不同的凭据路线，是否可用于两条业务、具体扣费来源和可用额度必须用真实账号与账单验证。若服务不支持，明确提示原因，不得静默切换到其他 Key、扣费账户或模型。

本文中的「一键」是**一个入口自动完成环境检查和继续流程**；QQ 与 B 站分别属于不同平台，首次授权仍需要用户分别扫码、确认和选择互动范围。不要承诺一次扫码能授权两个平台，也不要把 QQ 官方机器人描述成个人 QQ 登录或同步好友列表。

## 用户流程

1. 用户右键主角色 →「开始养鱼」，或打开工作台左下角现有养鱼设置；不增加开屏教程和强制新手引导。面板主界面保留「一键养鱼／全部暂停」「B 站扫码」「QQ 扫码」及简短状态；B 站的人设、作息、权限、推送、Cookie 和诊断，QQ 的服务范围、模型、手动凭据和连接管理，以及启动渠道选择全部默认折叠。等待授权可自动切换到对应扫码页，详细设置保留原保存方式。
2. 面板清楚展示工作台账号、B 站、QQ 机器人和运行状态。检查工作台账号是否已登录、模型路线是否可用；余额或额度查询不可用时显示「无法确认」，不能显示为零或保证有额度。
3. 用户选择要启用的渠道。缺少 B 站或 QQ 授权时，按顺序在同一个面板显示各自二维码；由用户完成手机确认，已授权渠道自动跳过。取消、超时或失败时显示重试/暂停，不把未验证状态显示为成功。
4. QQ 由用户选择私聊和群聊的服务范围；B 站阅读默认可用，公开评论、私信等写入需用户明确开启对应选项。QQ 扫码完成只是绑定凭据，网关连接和消息可用需分别显示。不得默认开放所有 QQ 用户或自动发布 B 站内容。
5. 被选渠道完成必要条件后自动继续，不需要再次逐项输入配置。未选择的渠道不阻止其他渠道启动；正在等待授权时用户可暂停。重启后保留已保存的设置与授权状态，但是否自动恢复运行遵循用户的已保存选择和实际登录验证。

## 当前实现与缺口

- **工作台和账号：** `apps/neko-workbench/runtime-config.cjs` 设定 DSH 默认账号路线；主角色独立 Chat API 的 Key 和 DSH 账号凭据是不同存储。不能仅因看见账号已登录就假定两条业务的模型调用和扣费都已验证。
- **B 站养鱼：** 已内置 `dsh-bili-whale`、右键启动和设置面板，具备账号检查、B 站扫码及暂停链路。此前实机验证到二维码生成与设置保存；本次真实只读阅读和两份日记已完成；扣费、夜间实际定时执行及平台写操作仍未验收。参见 [养鱼实现说明](../apps/neko-workbench/IMPLEMENTATION_v0.20.md)。
- **QQ 机器人：** 已在同一面板加入腾讯官方插件 `@tencent-connect/dsh-qqbot@0.5.3`；显式开始后准备依赖并显示扫码，首次准备需要 npm 和网络。真实二维码、绑定、重启恢复及私聊收发已验证；费用未核对。当前私聊、群聊默认禁用，QQ 会话为纯聊天，文件投递和本机工具调用关闭。
- **模型路线：** 本地适配约束新建、恢复及已缓存会话的账号路线，防止 QQ 上游偏好或工作台手动切换覆盖下一次渠道调用。自动化测试验证 provider/model 选择；两渠道的真实计费来源与额度仍须在用户自愿联调时核验。
- **记忆边界：** 养鱼日记、工作台 Chat API 轻量记忆和 N.E.K.O. 原生记忆目前未自动同步。本任务不把授权或账号整合描述成记忆整合；角色身份、日记与其他记忆的可控同步另列任务。

## 状态与接口约定

总体流程：`已暂停 → 检查账号与所选渠道 → 等待 B 站扫码 / 等待 QQ 扫码 → 检查访问范围 → 准备就绪 → 运行`。每个渠道保留自己的 `未启用 / 等待授权 / 已绑定 / 已连接 / 运行中 / 失败 / 已暂停` 状态；界面用实际回调更新。QQ 已绑定不得等同 QQ 网关已连接，模型登录成功不得等同余额足够。

协调器对用户启动与暂停使用串行化或代次取消：连续点击不重复创建 scheduler、QQ 连接或模型请求；等待扫码时暂停后，迟到的授权回调不能自动重新启动。对已有授权先验证有效性，失效时只重做受影响渠道。工作台退出、登录退出、模型不可用或网络异常时明确显示状态并允许重试。

QQ 原生会话可能有单独的模型和预设偏好。统一路线应明确指定账号 provider、模型和会话恢复策略，证明优先级不会被旧偏好覆盖；失败不回退到其他 Key。不得在渲染器、QQ 消息、日志、仓库或任务文档中暴露凭据。

## 验收

- [ ] 首次从主角色入口启动，在一个设置面板中按需完成 B 站与 QQ 的各自扫码；已授权时再次启动不要求重复扫码。
- [ ] 只选 B 站或只选 QQ 时，另一渠道不阻挡；扫码取消、失效、失败及多次点击可恢复，暂停后不再继续启动。
- [ ] 在模拟服务中分别捕获 B 站和 QQ 对话所用 provider/model，验证新会话、已存在会话、重启及登录失效路径均使用指定工作台账号路线；无权限或不可用时明确失败、不静默改用 API Key。
- [ ] 用户自愿登录后，在本机完成一次真实 B 站阅读/日记和一次真实 QQ 机器人收发；核对工作台账号的实际使用记录或账单，记录可见证据与仍不可确认的项目。不得只凭二维码或模拟测试宣称成功；真实调用和费用由用户掌握。
- [ ] B 站默认无公开写操作；QQ 服务范围按用户设置，默认不开放所有人。未经选择不发送评论、私信或群消息；QQ 会话不能调用本机文件/终端工具。
- [ ] QQ 授权、配置与会话偏好只保存在当前工作台独立目录，权限受限；不读取或修改旧版全局存档，日志、仓库和界面不暴露凭据。
- [ ] 跑相关渠道测试、`npm run check:neko` 和 `npm run test:neko`；记录具体系统与未测平台。对真实登录、扣费、社交收发分别记录验收结果。

## 非本任务

不实现个人 QQ 好友/群列表同步，不自动代用户发消息，不强制充值或购买；不实现 N.E.K.O. 双向记忆同步，不把 QQ 官方机器人接入等同已完成 N.E.K.O. 社区聊天室。以上可在单独任务中讨论。
